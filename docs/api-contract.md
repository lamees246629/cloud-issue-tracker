# API Contract: Issues API

## Data Dictionary: Issue

| Field | Type | Source | Rule |
|---|---|---|---|
| `id` | string | Server | Unique and immutable; generated by the API. |
| `title` | string | Client | Required; trimmed; 3–100 characters. |
| `description` | string | Client | Required; trimmed; 5–500 characters. |
| `priority` | string enum | Client | `Low`, `Medium`, or `High`. |
| `status` | string enum | Server / controlled update | `Open` or `Resolved`; new issues start `Open`. |
| `createdAt` | ISO 8601 string | Server | Generated when created; immutable. |

Create requests may include extra properties, but the API only uses `title`,
`description`, and `priority`; clients cannot choose `id`, `status`, or
`createdAt`. JSON request bodies are limited to 65,536 bytes. The service stores
issues in `backend/data/issues.json`.

A complete issue returned by the API:

```json
{
  "id": "ISS-<generated-uuid>",
  "title": "Unable to access Wi-Fi",
  "description": "Connection fails in the teaching lab.",
  "priority": "High",
  "status": "Open",
  "createdAt": "2026-10-13T07:00:00.000Z"
}
```

## Contract 1: View All Issues

- Request: `GET /api/issues`
- Request body: none
- Success: `200 OK` with a JSON array in insertion order.
- Empty result: `200 OK` with `[]`.
- Errors: `500 INTERNAL_ERROR` for unexpected file or server errors.

## Contract 2: Create an Issue

- Request: `POST /api/issues`
- Headers: `Content-Type: application/json` and `Accept: application/json`.
- Request body:

```json
{
  "title": "Projector not working in Lab 3",
  "description": "Laptop cannot detect the classroom projector.",
  "priority": "High"
}
```

- Success: `201 Created` with the complete created issue as JSON and a
  `Location` header pointing to `/api/issues/{id}`.
- Errors: `400 VALIDATION_ERROR` for malformed JSON or fields that violate the
  data rules; `413 REQUEST_TOO_LARGE` when the body exceeds 65,536 bytes;
  `415 UNSUPPORTED_MEDIA_TYPE` when the content type is not JSON;
  `500 INTERNAL_ERROR` for unexpected failures.

## Contract 3: Change Issue Status

- Request: `PATCH /api/issues/{id}/status`
- Headers: `Content-Type: application/json` and `Accept: application/json`.
- Request body:

```json
{
  "status": "Resolved"
}
```

- Success: `200 OK` with the complete updated issue as JSON. Only its `status`
  field changes.
- Errors: `400 VALIDATION_ERROR` for malformed JSON or a status other than
  `Open` or `Resolved`; `404 ISSUE_NOT_FOUND` when `{id}` does not exist;
  `413 REQUEST_TOO_LARGE` when the body exceeds 65,536 bytes;
  `415 UNSUPPORTED_MEDIA_TYPE` when the content type is not JSON;
  `500 INTERNAL_ERROR` for unexpected failures.

## Error Response

Every API error uses this JSON shape:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Title must contain between 3 and 100 characters."
  }
}
```

| Status | Code | Returned when |
|---|---|---|
| `400` | `VALIDATION_ERROR` | JSON is malformed or request fields violate a rule. |
| `404` | `ISSUE_NOT_FOUND` | The requested issue ID does not exist. |
| `404` | `ROUTE_NOT_FOUND` | The API path is not recognized. |
| `413` | `REQUEST_TOO_LARGE` | A JSON request body exceeds 65,536 bytes. |
| `415` | `UNSUPPORTED_MEDIA_TYPE` | A JSON endpoint receives a non-JSON content type. |
| `500` | `INTERNAL_ERROR` | An unexpected server or data-file error occurs. |
